# Cloudflare — DNS/WAF/CDN + R2 (Spec §6, §24)

Cloudflare sits in front of the platform for DNS, WAF and CDN, and provides
R2 as the private object store.

## DNS / WAF / CDN

- All public hostnames (tourist, guide, admin frontends on Vercel; api on
  Render) are CNAMED through Cloudflare with proxying (orange-cloud) enabled
  so TLS, WAF and caching apply.
- SSL/TLS mode: **Full (strict)** — origin certs from Vercel/Render.
- WAF: managed ruleset on; rate-limit rules on auth, OTP/SMS and payment
  webhook endpoints (Spec §24 launch checklist).
- CDN caching applies to static frontend assets only; API responses and
  signed media URLs are never cached at the edge.

## R2 — private object storage

- One **private** bucket (`R2_BUCKET_PRIVATE`) holds guide verification
  files, generated receipts/invoices and other non-public objects
  (Spec §6, §14).
- Objects are served **only** via short-lived signed URLs generated by the
  api service — the bucket is never public and has no public bucket domain.
- CORS: no browser-direct access; uploads/downloads go through the api.
- Credentials are S3-compatible and injected into the Render services via
  env vars (names per `.env.example` / Spec §25):
  - `R2_ENDPOINT`
  - `R2_ACCESS_KEY_ID`
  - `R2_SECRET_ACCESS_KEY`
  - `R2_BUCKET_PRIVATE`

Use a scoped R2 API token (read/write on this bucket only), one token per
environment; rotate with the platform secrets.
